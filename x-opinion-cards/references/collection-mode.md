# 观点库采集模式

用于分批读取某位 X 博主的帖子，积累可选择的观点。这里的“轮询”指分页或分批继续读取历史帖子；不表示后台常驻或定时任务。

## 必要输入

开始前必须明确：

- 博主或主页链接；
- **目标观点数**，即本次希望最终列出的合格观点数量。

主题、日期范围、最多扫描帖子数是可选条件。用户未提供目标观点数时，只询问这一项，不自行猜测。若用户要求“所有观点”，说明平台访问无法保证穷尽全量，并请用户给出本批目标观点数。

## 分批读取与停止条件

从上次游标继续；没有游标时从可访问的最新帖子开始。按页面或检索批次读取，保存每批最旧/最新帖子标识和访问渠道。遇到以下任一条件停止：

1. 新增合格观点达到本次目标；
2. 达到用户给出的扫描上限或日期边界；
3. 可访问结果耗尽、连续三个批次没有新帖子，或访问被阻断；
4. 继续获取需要新的登录、付费 API 或用户授权。

如果目标未达成，交付已经核实的观点并写明停止原因，不补造内容。计数时区分“扫描帖子数”和“合格观点数”。线程可形成一个或多个独立观点，但同一语义只计一次。

## 去重与编号

- 原帖 ID / 永久链接完全相同：直接去重。
- 同一作者重复表达相同主张：保留上下文更完整、表达更清楚的一条；其余链接可记为相关来源，不增加观点计数。
- 观点编号按作者永久递增，例如 `DK-0001`、`SB-0001`、`JC-0001`、`JW-0001`。继续采集时不得重排或复用旧编号。
- 删除或无法访问的帖子保留历史记录并标注状态，不把编号分配给另一观点。

## 保存结构

在 `outputs/x-opinion-cards/<作者目录>/观点库/` 保存：

```text
观点库/
  index.md
  items/
    DK-0001.md
    DK-0002.md
  runs/
    2026-09-27-目标30条.md
  state.json
```

`index.md` 是供用户选择的总表，至少包含编号、直白标题、完整中文观点、主题、原帖日期、原帖链接、处理类型与状态。

每个 `items/<编号>.md` 保存作者、主页、原帖永久链接、帖子 ID、发布日期、访问日期、获取渠道、必要原文摘录、中文处理类型、完整中文观点、主题标签、相关重复来源和状态。

`runs/<日期-目标数>.md` 记录本次目标、新增合格观点数、扫描帖子数、覆盖日期、起止游标、失败项与停止原因；同日重跑时追加序号，避免覆盖。

`state.json` 至少保存作者主页、下一编号、已见帖子 ID、最近游标、最后成功访问时间和最后覆盖日期。它只记录实际取得的状态，不能把搜索结果页码冒充 X 的官方游标。

## 交付格式

先给简洁统计，再按稳定编号列出本批新增观点。每条至少显示完整中文观点和原帖链接，让用户可以直接回复“生成 DK-0003、DK-0008”。未达到目标时同时说明还差多少以及停止原因。
